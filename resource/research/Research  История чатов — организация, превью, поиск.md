# Research: История чатов — организация, превью, поиск

**Продукт:** Perplexity-like AI-поиск | **Фича:** История чатов (организация + превью + поиск)
**Волна:** 1 (core loop) | **Версия:** 1.0 | **Дата:** март 2026

***

## 1. Боли и потребности

### Jobs to be done

История чатов выполняет три разные работы: **найти конкретное** ("где был тот разговор про налоговый вычет"), **вернуться к незаконченному** ("продолжить исследование"), **убедиться что система помнит** (ощущение накопленного контекста). Это не второстепенная фича — для регулярных пользователей это главная точка входа.

**Ключевые боли:**

- **"Я не могу найти нужный чат"** — при накоплении > 20–30 чатов поиск становится критическим. Пользователи ChatGPT жалуются на невозможность найти конкретный разговор и вынуждены создавать дубликаты.[^1]
- **Бесконечный скролл** — плоский список без группировки или поиска превращается в хаос.[^2][^1]
- **Потеря хронологии** — когда ChatGPT убрал группировку "Сегодня / Вчера / 7 дней", пользователи были возмущены. Временные метки — это не декорация, а основная навигация.[^3][^4]
- **Неинформативные заголовки** — автоматически генерируемые названия чатов зачастую одинаковые и не различимы.[^5]
- **Нет превью без открытия** — чтобы понять нужный ли это чат, нужно его открыть.[^1]
- **Нет поиска или слабый поиск** — пользователи вынуждены экспортировать чаты и искать вручную.[^6][^2]

### Барьеры

- Накопление → хаос → пользователь перестаёт доверять истории и начинает заново
- Ощущение что "мои данные где-то потерялись" снижает доверие к продукту
- Сложная организация (папки, теги) требует усилий → большинство не пользуется

### Триггеры возврата

- Уведомление "вы не завершили исследование о..." (продолжение сессии)
- История как доказательство накопленной ценности: "у меня уже 50 чатов, здесь моя работа"
- Быстрое нахождение нужного чата → доверие к системе

## 2. Метрики

### Что показывает что фича работает

| Метрика | Что измеряет | Ориентир |
|---|---|---|
| History re-open rate | % сессий начинающихся с открытия старого чата | > 30% у активных пользователей |
| Search usage rate | % пользователей использующих поиск по истории | Рост при > 20 чатов |
| Time to find (returning user) | Время от открытия истории до нужного чата | < 15 сек |
| New chat from history | % новых чатов, начатых из истории (контекст продолжения) | — |

### Retention-связь

Функция истории напрямую связана с long-term retention: пользователь воспринимает историю как "свои данные" в продукте. Чем лучше история — тем выше switching cost: уйти к конкуренту = потерять накопленный контекст.[^7]

### Антиметрики

- Duplicate chat creation rate — создание нового чата вместо возврата к старому (сигнал что история не работает)[^1]
- Zero history sessions — пользователь открыл продукт, ничего не нашёл в истории, закрыл
- History panel ignored — сайдбар с историей никогда не открывается (у мобайл-пользователей)

## 3. Конкуренты — как решили

### Прямые конкуренты

| Конкурент | Организация | Поиск | Превью | Группировка | Особенности |
|---|---|---|---|---|---|
| **Perplexity** | Список + Spaces (платно) | Есть, но ограниченный[^2] | Нет превью — только заголовок | Хронологическая | Spaces = тематические коллекции с инструкциями для AI[^8] |
| **ChatGPT** | Список + Projects | Поиск по названию | Нет превью | Today / 7 days / 30 days / Year[^3] — убирали и вернули | Пины, архив, переименование |
| **Claude** | Список с Workspaces | Базовый поиск | Нет | Хронологическая | Разделение по воркспейсам[^7] |
| **GigaChat** | Простой список | Нет | Нет | Нет | Минималистично |
| **Яндекс Нейро** | В рамках Яндекс-истории | Через поиск Яндекса | Нет | Нет | Интегрирован в экосистему |

### Нереализованные паттерны (возможность сделать лучше)

- **Превью чата без открытия** — по данным UX case study по ChatGPT, пользователи хотят видеть несколько строк контента прямо в списке. Никто из основных конкурентов это не сделал хорошо.[^1]
- **Семантический поиск** — поиск не по ключевым словам заголовка, а по смыслу содержимого. Технически реализуемо, никто из конкурентов не предлагает.[^9][^1]
- **Table of contents внутри чата** — для длинных разговоров. Аналогично Google Docs / Linear — навигационная панель с разделами чата.[^10]

### Косвенные — UX-паттерны

**Gmail** — мастер организации: метки, звёздочки, папки, поиск по контенту. Главный урок: пользователи не хотят тратить время на организацию — нужна авто-категоризация.

**Telegram** — поиск по всем чатам мгновенный. Pinned messages как "закладки" внутри разговора.

**Notion** — Sidebar с иерархией страниц. Collapse/expand, drag & drop, поиск. Стандарт для работы с накопленным контентом.

## 4. Критерии хорошего решения

### Измеримые
- Пользователь находит нужный чат < 15 секунд при 50+ чатах в истории
- > 30% активных пользователей регулярно возвращаются к старым чатам (не только создают новые)
- Search используется > 20% пользователей с большой историей

### Субъективные
- История ощущается как "моя личная база знаний", а не как "список мусора"
- Продукт помнит — это основа доверия
- Легко отличить похожие чаты без открытия каждого

## 5. Что копируем и почему

### ChatGPT: хронологическая группировка с метками

**Что:** Группировка "Сегодня / Вчера / 7 дней / 30 дней / более старые".[^3]

**Почему работает:** Пользователь думает о времени ("когда я это спрашивал?"), а не об алфавите или теме. Временная группировка соответствует ментальной модели. ChatGPT убрал эту функцию — пользователи взбунтовались и потребовали вернуть. Сигнал: это baseline, не опция.[^4][^3]

### Perplexity: Spaces для тематической организации

**Что:** Spaces — тематические коллекции с кастомными инструкциями для AI. Позволяют группировать чаты по проекту или теме + дают AI контекст ("отвечай как финансовый советник").[^8]

**Почему работает:** Для power users — критически важно. Снижает повторные инструкции в начале каждого чата. Переносится как "продвинутый" уровень организации.

### Перенести паттерн Telegram: pinned chats

**Что:** Закреплённые чаты в топе списка — для тем которые пользователь исследует регулярно.

**Почему работает:** Простое решение для "важного и часто нужного". Не требует сложной системы папок.[^7]

***

## 6. Что делаем иначе и почему

### Превью чата прямо в списке

Никто из конкурентов не показывает превью контента в боковой панели. Добавить: при hover (десктоп) или long press (мобайл) — всплывающее превью первых 2–3 строк чата. Это устраняет необходимость открывать чат чтобы понять нужный ли это.[^1]

### Автогенерация точных заголовков + возможность переименовать

AI-продукты часто генерируют неточные или похожие заголовки ("Вопрос о налогах", "Вопрос о налогах 2"). Делаем: более специфичный автозаголовок (включающий ключевое слово запроса), плюс **inline edit** — клик на заголовок в списке → сразу редактируется без открытия чата.[^5]

### Семантический поиск по истории

Поиск не по заголовку, а по содержимому чата. Запрос "где я спрашивал про Испанию" → находит чат где была Испания, даже если заголовок был "Путешествие". Это возможность дифференциации — никто из прямых конкурентов не реализовал полноценно.[^2][^9][^1]

### Телеком-контекст: чаты связанные с аккаунтом оператора

Уникальная возможность: история привязана к аккаунту пользователя оператора, а не к отдельному AI-аккаунту. Пользователь видит историю на всех устройствах без дополнительной регистрации — снижает friction и усиливает retention.

***

## 7. Что не делаем

### Не делаем сложную систему тегов/папок по умолчанию

Большинство пользователей не будут вручную организовывать историю. Ручная организация должна быть опцией, но не обязательным шагом. Автоматическая группировка по времени + автозаголовки — это baseline.[^1]

### Не удаляем хронологическую группировку

Урок от ChatGPT: пользователи воспринимают это как регрессию и активно жалуются. Хронология — не опция, это обязательный базовый уровень.[^4][^3]

### Не прячем историю глубоко в навигации

История — это core feature для retention. Она должна быть доступна с первого экрана, в одно действие.[^11]

### Не ограничиваем поиск только заголовками

Поиск только по заголовку бесполезен если заголовки автоматические и похожие. Поиск должен работать по содержимому с самого начала.[^2][^5]

### Не показываем бесконечный плоский список без группировки

Даже при 10 чатах плоский список некомфортен. При 50+ — катастрофа.[^3][^1]

## 8. Рекомендации

### R1 — Хронологическая группировка с четкими метками (обязательно)

**Сделать так:** Сегодня / Вчера / На этой неделе / В этом месяце / [Месяц Год]. Каждая группа сворачиваемая. Метки всегда видны при скролле (sticky headers).

*Почему:* Соответствует ментальной модели пользователя. Базовый стандарт который нельзя убирать.[^4][^3]

### R2 — Превью контента при hover / long press

**Сделать так:** Десктоп — всплывает карточка с первыми 2–3 строками чата при наведении. Мобайл — long press открывает bottom sheet с превью + действиями (переименовать / закрепить / удалить).

*Почему:* Устраняет главную боль "не знаю нужный ли это чат без открытия". Конкуренты не сделали.[^1]

### R3 — Умный автозаголовок + inline rename

**Сделать так:** Автозаголовок = ключевое слово из первого запроса (не пересказ, а суть). Переименование — одиночный клик на заголовок в списке, без модалки.

*Почему:* Пользователи не хотят тратить время на переименование, но хотят различимые чаты.[^5]

### R4 — Поиск по содержимому с подсветкой

**Сделать так:** Строка поиска в топе истории. Поиск по заголовку + содержимому. Результаты — карточки с подсветкой найденного фрагмента. Фильтр по дате (диапазон).

*Почему:* При накоплении истории это становится критически важным. Пользователи готовы платить за сохранение истории именно потому что хотят к ней возвращаться.[^2]

### R5 — Закреплённые чаты (пины)

**Сделать так:** Долгое нажатие → "Закрепить". Закреплённые чаты — отдельная секция в топе истории. Лимит: 5 закреплённых.

*Почему:* Простое решение для "постоянно нужного" без сложных папок.[^7]

### R6 — Spaces / Коллекции как продвинутая организация (не для MVP)

**Сделать так:** После MVP — возможность создать тематическую коллекцию (например "Работа", "Путешествие"). Чаты можно добавлять вручную или автоматически. Коллекция может иметь системную инструкцию для AI.

*Почему:* Power users нуждаются в более сложной организации. Это фича роста, не core.[^8]

### R7 — Table of contents внутри длинного чата

**Сделать так:** Для чатов с > 10 обменами — автоматическая навигационная панель внутри чата. AI определяет смысловые блоки ("Общий вопрос → Уточнение → Итоги"). Тап → прыжок к нужному месту.

*Почему:* Решает проблему "вечного скролла" внутри длинных исследовательских сессий. Аналог Google Docs / Notion ToC.[^10]

## 9. Открытые вопросы

### Для проверки с пользователями

- [ ] Как пользователи формируют ментальную карту своей истории — по времени, теме или продукту?
- [ ] Превью: полезно на мобайле или только на десктопе?
- [ ] Насколько пользователи готовы вручную организовывать историю (переименовывать, раскладывать по коллекциям)?
- [ ] Семантический поиск: пользователи поймут что можно искать по смыслу, а не точной фразе?

### Для уточнения с командой

- [ ] Хранение истории: есть ли лимит? Бесплатный аккаунт = X чатов / платный = бесконечно?
- [ ] Синхронизация между устройствами: доступна с первого дня?
- [ ] Семантический поиск: технически реализуемо через векторный поиск по эмбеддингам чатов?
- [ ] Table of contents: это AI-фича или алгоритмическая обработка чата?
- [ ] Spaces в MVP или это следующая волна?
